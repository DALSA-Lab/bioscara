\doxysubsection{Detailed Description}
The bioscara gripper hardware interface class. 

System interface has been chosen to allow future modifications for grippers that provide feedback. refer to the \doxylink{classbioscara__hardware__interfaces_1_1BioscaraArmHardwareInterface}{Bioscara\+Arm\+Hardware\+Interface} class for a more detailed description of the hardware life-\/cycle.

{\footnotesize\ttfamily hardware\+\_\+interface\+::\+Callback\+Return bioscara\+\_\+hardware\+\_\+interfaces\+::\+Bioscara\+Gripper\+Hardware\+Interface\+::on\+\_\+error (\begin{DoxyParamCaption}\item[{const rclcpp\+\_\+lifecycle\+::\+State \&}]{previous\+\_\+state }\end{DoxyParamCaption})\hspace{0.3cm}{\ttfamily [override]}}



Called when an error in any state or state transition is thrown. 

According to the \href{https://control.ros.org/jazzy/doc/ros2_control/hardware_interface/doc/hardware_components_userdoc.html\#handling-of-errors-that-happen-during-read-and-write-calls}{\texttt{ ros2\+\_\+control documentation}}\+:

\begin{quote}
Error handling follows the node lifecycle. If successful Callback\+Return\+::\+SUCCESS is returned and hardware is again in {\ttfamily UNCONFIGURED} state, if any ERROR or FAILURE happens the hardware ends in {\ttfamily FINALIZED} state and can not be recovered. The only option is to reload the complete plugin, but there is currently no service for this in the Controller Manager. \end{quote}


Since the hardware will immediatly return to the {\ttfamily unconfigured} state (\href{https://github.com/ros-controls/ros2_control/blob/d0836b7f12b89acb89bde83d4ba4308513b03204/hardware_interface/src/hardware_component.cpp\#L247}{\texttt{ source}}) if the error could be handled we manually call the transition functions which would normally be called to this state. Those are\+:
\begin{DoxyItemize}
\item {\bfseries{Previous state}}\+: {\ttfamily active}
\begin{DoxyItemize}
\item Deactivate hardware (\doxylink{classbioscara__hardware__interfaces_1_1BioscaraGripperHardwareInterface_ab199edb3ee4a278fc8f5a24c2536fc14}{on\+\_\+deactivate()}) -\/\texorpdfstring{$>$}{>} {\ttfamily inactive}
\item Clean-\/\+Up hardware (\doxylink{classbioscara__hardware__interfaces_1_1BioscaraGripperHardwareInterface_a5adcd99396a192989faaaaea5aeeffc1}{on\+\_\+cleanup()}) -\/\texorpdfstring{$>$}{>} {\ttfamily unconfigured}
\end{DoxyItemize}
\item {\bfseries{Previous state}}\+: {\ttfamily inactive}
\begin{DoxyItemize}
\item Deactivate hardware (\doxylink{classbioscara__hardware__interfaces_1_1BioscaraGripperHardwareInterface_ab199edb3ee4a278fc8f5a24c2536fc14}{on\+\_\+deactivate()}) -\/\texorpdfstring{$>$}{>} {\ttfamily inactive}
\begin{DoxyItemize}
\item call the deactivate function anyway regardless if state was active or inactive.
